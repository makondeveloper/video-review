# 영상 검수 (로컬 전용)

편집이 끝난 영상을 보면서 고칠 곳을 타임라인에 마킹하는 웹 도구.
기록은 영상 옆에 `<영상 파일명>.review.json` 으로 자동 저장되고,
검수 완료를 누르면 `<영상>.검수정리.md` 가 만들어져 편집 쪽(재편집)이 읽는다.

## 다른 컴퓨터에 설치 (처음 한 번)
PowerShell 을 열고 아래 한 줄을 붙여 넣고 Enter:

```powershell
irm https://raw.githubusercontent.com/makondeveloper/video-review/main/install.ps1 | iex
```

- `문서\video-review` 에 설치되고, 바탕화면에 **영상 검수** 바로가기가 생기고, 바로 켜진다.
- 따로 설치할 것 없음(Git·Node 필요 없음). 인터넷만 있으면 된다.
- 한 줄 명령이 싫으면: GitHub 페이지 → `Code` → `Download ZIP` → 풀어서 `문서\video-review` 에 두고 `start.cmd`.

## 업데이트 (자동)
- `start.cmd`(바로가기)로 켤 때마다 GitHub 에 새 판이 있으면 **자동으로 받아서** 켠다. 할 일 없음.
- 인터넷이 안 되면 업데이트만 건너뛰고 지금 판으로 켜진다.
- 그 컴퓨터의 마지막 폴더(`last-dir.txt`)와 검수 기록(영상 옆 파일)은 업데이트해도 그대로다.
- 이미 켜져 있는 서버는 바뀌지 않는다 → 검은 창을 닫고 다시 켜면 새 판.
- 개발하는 컴퓨터(폴더에 `.git` 이 있는 곳)는 자동 업데이트를 건너뛴다. 고친 뒤 GitHub 에 올리면 다른 컴퓨터가 받는다.

## 켜기
- `start.cmd` 를 더블클릭하면 브라우저에서 `http://localhost:5178` 이 열린다.
- 영상 폴더를 `start.cmd` 위로 끌어다 놓으면 그 폴더로 바로 시작한다.
- 영상 고르기: 위의 `📂 파일 열기` → 윈도우 파일 열기 창에서 영상을 고르면 그 폴더가 열리고 영상이 바로 뜬다.
  경로 칸에 **폴더나 영상 파일 경로를 붙여 넣고 Enter** 해도 된다(따옴표 붙은 "경로 복사" 그대로 OK). 칸의 ▼ 목록은 최근에 연 폴더 8개.
  마지막 폴더는 `last-dir.txt` 에 기억해서 다음에 켤 때 그 폴더로 시작한다.
- 끄기: 검은 창에서 Ctrl+C 또는 창 닫기.
- 설치할 것 없음 (Windows PowerShell 만 씀). 기본은 `localhost` 로만 열려서 다른 컴퓨터에서는 접속 못 한다.

## 같이 보기 (같은 사무실 와이파이)
- 기본은 **나만 보기**. 영상을 고른 뒤 위의 `👥 같이 보기` → `이 영상 같이 보기 켜기` 를 누르면 링크(`http://내컴퓨터IP:5180/?k=…`)가 생긴다. 복사해서 보내면 된다.
- 링크는 **그 영상으로 고정**된다. 받은 사람은 링크를 열면 그 영상이 바로 나오고, 다른 영상은 못 연다.
  내가 다른 영상으로 옮긴 뒤 `지금 보는 영상으로 바꾸기` 를 누르면 링크는 그대로 두고 보는 사람 화면도 그 영상으로 바뀐다.
- 링크로 들어온 사람도 **마킹·수정·삭제**를 할 수 있다. 서로 고친 내용은 3초 안에 양쪽 화면에 합쳐진다.
  폴더·영상 바꾸기, 검수 완료, fps, 같이 보기 끄기는 나(서버 켠 사람)만 할 수 있다.
- 동시에 고쳐도 안 덮어쓴다: 파일에 판 번호(`rev`)가 있어서, 그 사이 다른 사람이 저장했으면 최신 판을 받아
  **마커별로** 합친 뒤 저장한다. 같은 마커를 둘이 고치면 나중에 고친 쪽이 남고, 지운 마커는 `deleted` 에 기록돼 다른 화면에서도 지워진다.
  다른 사람 수정이 합쳐지면 그 화면의 되돌리기(Ctrl+Z) 기록은 비워진다.
- 공유 중에는 버튼에 `👥 같이 보는 중 · N명` 으로 지금 링크로 보고 있는 사람 수가 뜬다 (나 빼고, 3초마다 갱신. 창을 닫으면 10초 안에 빠진다). 보는 사람 화면에도 인원이 뜬다.
- `같이 보기 끄기` 를 누르면 링크가 바로 막힌다. 다시 켜면 새 링크가 생기고 예전 링크는 안 열린다.
- **처음 한 번만** `같이보기-준비.cmd` 를 더블클릭하고 윈도우가 물으면 `예`. (5180 포트를 같은 와이파이 기기에만 열어 준다.)
  되돌리기: `powershell -ExecutionPolicy Bypass -File share-setup.ps1 -Remove`
- 영상은 내 컴퓨터에서 나가므로 내 컴퓨터와 검은 서버 창이 켜져 있어야 한다.

## 영상 형식
브라우저가 재생할 수 있어야 한다. 프리미어에서 **H.264 .mp4** 로 내보낸 파일로 검수한다.
(ProRes .mov, 일부 HEVC 는 브라우저가 못 연다.)

## 쓰는 법
- 보다가 고칠 곳에서 `M` → 마커가 찍히고 잠깐 멈춤 → 메모 쓰고 `Enter` → 이어서 재생.
- 구간: `I`(시작) `O`(끝) 찍고 `M`, 또는 타임라인 마커 줄 빈 곳을 끌기. 마커 양 끝을 끌면 길이 조절.
- 종류 버튼을 누르거나 숫자키를 누르면 그 종류로 바로 마킹된다: `1` 컷편집 · `2` 자막 · `3` 소리 · `4` 효과음 · `5` 효과 · `6` 화면 · `7` 기타. `M`은 마지막에 쓴 종류로 마킹.
- 이동: `Space` 재생, `←/→` 1프레임, `Shift+←/→` 1초, `↑/↓` 이전·다음 마커, `Ctrl+휠` 타임라인 확대.
- 전체화면: `F`(또는 영상 더블클릭)는 영상만 크게 보여 주고, 아래 얇은 막대에 마커가 표시된다. 이 상태에서도 `M` 마킹과 메모가 된다. `Shift+F`는 타임라인까지 통째로 전체화면. 다시 누르거나 `Esc`로 끝.
- 전부 보고 나면 위의 `검수 완료` → 파일의 `status` 가 `done` 이 되고, 영상 옆에 **`<영상>.검수정리.md`** 가 만들어진다.
  고칠 곳 표(R01…·시각·종류·메모)와 재편집 순서(컷편집은 맨 끝에 뒤에서부터)가 들어 있다. 뜨는 창에서 경로를 복사해
  편집 오피스 Main Header에 넘기면 재편집 세션이 이 파일을 읽는다 (구조안 v4.1 11장).
  검수를 다시 열면 정리 파일 맨 위가 "검수 중"으로 바뀌어 재편집에 쓰이지 않는다.
- 마커 편집 칸의 **`앞으로도 이렇게`** 체크: 이 영상만이 아니라 다음 영상에서도 지킬 규칙이면 체크한다.
  목록에 `★ 앞으로도`가 붙고, 정리 파일의 "원칙 후보"에 모여 편집 오피스가 원칙집 후보로 올린다(구조안 11-10).
- 전체 단축키는 화면의 `단축키` 버튼.

## 기록 파일 형식 (`<영상>.review.json`)
편집 코드는 `status === "done"` 인 파일만 읽는다.

```json
{
  "version": 1,
  "video": "1편.mp4",
  "videoPath": "D:\\편집\\완성본\\1편.mp4",
  "duration": 612.48,
  "fps": 30,
  "width": 1920, "height": 1080,
  "status": "done",               // in_review | done
  "doneAt": "2026-11-23T01:00:00.000Z",
  "markers": [
    {
      "id": "m…",
      "type": "cut",              // cut 컷편집 | subtitle 자막 | audio 소리 | sfx 효과음 | effect 효과 | visual 화면 | other 기타
      "kind": "range",            // point(한 지점, start=end) | range(구간)
      "start": 12.5, "end": 14.2, // 초 (기준값)
      "startTC": "00:00:12:15", "endTC": "00:00:14:06", // 사람이 읽는 용 (HH:MM:SS:FF)
      "note": "말 더듬은 부분 잘라 주세요",
      "applied": false,           // 편집 코드가 반영하면 true 로 바꾸는 칸
      "createdAt": "…", "updatedAt": "…"
    }
  ]
}
```

- 시간은 **완성본(내보낸 영상) 기준**이다. 프리미어 시퀀스 시간으로 옮길 때는 내보내기 시작점을 더한다.
- `start`/`end` 가 기준값이고 `startTC`/`endTC` 는 저장할 때 `fps` 로 다시 계산한다.
